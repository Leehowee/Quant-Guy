# ETF短线交易复核规则

本模块为数天至两周持有周期生成候选观察表，不下单。初始阈值是待验证参数，不能视为已验证的收益保证。

## 市场过滤

- 指数收盘高于20日均线，且全市场上涨家数占比不低于50%：权益仓位上限60%。
- 只有一项满足：权益仓位上限30%。
- 两项都不满足：不新开仓。
- 缺少目标日市场快照、20日均线或有效上涨家数比例：状态为数据不足，不开仓。

每日行业任务盘后读取AKShare的A股涨跌幅快照及上证指数日线，保存到 `data/processed/market_regime_history.csv`。盘后快照日期按运行交易日标记，属于时点采集记录；供应端无有效交易日期时，报告保留采集时间，不声称获得逐账户交易数据。

如果缺少历史指数收盘，可运行 `python bin/run_market_backfill.py --sessions 40` 回溯指数日线和20日均线。回溯不会填入历史上涨家数；目标日上涨家数缺失时，市场状态仍是“数据不足”，ETF候选继续暂停。

## ETF候选过滤

候选需要同时满足：

1. 目标日前20个交易日ETF收盘价完整，当前价格高于20日均线。
2. 最近5个交易日ETF份额变化估算净申购总额大于0，且至少3天为正。
3. 最近10个交易日ETF涨幅高于上证指数同期涨幅。
4. 目标日市场快照完整，且市场状态不是“较弱”或“数据不足”。

ETF估算净申购继续使用份额变化乘以收盘价，只作为份额变化线索。它不等于可核验现金流，也不说明申购者身份。每日复核保存到 `data/processed/trade_review_YYYYMMDD.csv`。

## 账户风险

- 单笔风险预算为账户净资产的0.3%；回撤4%至6%时减半。
- 全部持仓到退出参考位的计划风险上限为账户净资产的1.2%。
- 单只ETF不超过15%，同主题合计不超过20%，总敞口遵守市场状态上限。
- 回撤达到6%暂停新开仓，达到8%减仓复核；达到10%为策略最大容忍回撤目标，但跳空、跌停或流动性不足可能造成超限。
- T+1、买卖价差、费用、跳空、涨跌停和不可成交风险仍需在实盘记录中核算。

账户回撤与现有持仓不在行情数据源中，因此日报会展示规则摘要和“账户参数未接入”状态，不替用户生成个性化股数；`size_etf_position` 仅在调用方提供账户净资产、已有敞口、已有风险、入场价和退出参考价后，计算手数取整后的仓位上限。仓位管理函数按初始退出位、2倍ATR跟踪退出、达到10个交易日退出、持仓3日仍未走强的顺序返回首个退出条件。

## 主体持仓跟踪

`config/holder_watchlist.csv`列出公开信息研究对象。ETF图片日报显示该名单和手动录入状态。可将核验过的组合名称、证券代码、持股数量、持仓截止日和公告日录入 `config/holder_observations.csv`（字段模板见 `config/holder_observations_template.csv`），再用 `compare_public_holdings` 比较相邻两期。同名账户需按公告原名保存。该表不冒充账户级实时资金流；公开持仓抓取接口尚未作为数据源接入。

定期持仓仅描述报告期末情况。报告披露之前不可作为可交易信息；账户掉出前十名不应填成零；同一主体的关联公司不得在未核实一致行动关系前重复合并。

## 验证

运行：`python -m unittest discover -s tests -v`。至少对照固定基准持有、单纯价格趋势、价格趋势加资金过滤三组策略，记录扣除费用后的收益、回撤、换手率、最差连亏和数据缺失率。当前仓库数据较短，新规则上线后需积累足够历史并进行样本外验证，才能判断资金过滤是否增加价值。
